# Admin 迁移：模块议题与验收台账

本台账是工作范围与验收约束，不是完成报告。固定上游为 material-kit-react `69e780a40c455d664b2e13c525faf1d492a072a7`。从 2026-10-18 起，每个模块作为独立议题处理：先复核上游行为，再决定适配，执行相同行为测试，记录差异。源码已读不等于行为已验证；原版通过不等于迁移版通过。

## 2026-10-19 范围修正：框架优先

Admin 的定位是 cormi 的真实兼容性与生命周期测试负载，不是独立产品开发目标。当前任务以 [框架能力矩阵](../35-framework-validation.md) 为主：配置、插件、路由生成、运行时、构建与开发接口。以下 AM 条目保留负载映射和历史证据；Users 的分页/全选语义、Header 焦点、商品/文章业务及完整图表交互不再自动构成 cormi 待办或发布门槛。仅在确认由框架造成退化或阻塞具体框架功能时处理相关适配，不删除已有测试或伪造关闭。

## 统一交付与状态规则

每项必须有来源文件、原版真实行为/占位行为、cormi 接入位置、失败和组合场景、实际证据、未完成项。状态分为待核对、基线完成、适配中、对照通过、有阻塞。只有同一条行为契约在原版与迁移版均执行，或明确记录差异及批准的取舍，才能写对照通过。未知情况不能记成不适用或默认通过。功能计数以行为为单位；截图、HTTP 200、单元测试数量均不能代表某模块完成。

原版缺陷保留可复现记录，不能悄悄修掉后伪造相同基线；需要修正时作为单独变更，给出原版与改进版预期。没有真实业务能力的按钮也必须记录，而不是把点击无报错称为功能正常。后续新增 API、权限或持久化属于验证扩展，与忠实迁移分开。

## 模块关闭门槛

不能删除原来的路由、组件、图表、样式或错误界面来让构建通过；不能绕开 cormi 用原来的 Vite 启动器获得“迁移成功”；不能加入第二个 RouterProvider；不能把业务源码强制 any 或关闭检查来完成 typecheck；不能将异常请求/控制台错误统一过滤。

发现问题先区分上游行为、测试假设、适配错误、框架缺口、第三方依赖/环境差异。错误需独立重现，修复后重复原断言并运行受影响模块和共享回归。每轮汇报已关议题、仍开议题及证据，不只报总测试数。测试组件修改只在隔离副本进行，原参考 checkout 永远不承担实验性改动。

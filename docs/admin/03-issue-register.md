# Admin 问题登记：不要混淆基线、退化与功能增强

固定上游 `69e780a40c455d664b2e13c525faf1d492a072a7`；关联 [模块台账](00-module-ledger.md)。本文件列的是待处理议题，不将记录问题等同于修复。原版源码保持不变，迁移版尚未执行。

## UP-01 / AM05：过滤后的分页总数不对应结果

分类：原版行为缺陷，已在原版页面复现。进入 Users，搜索一个唯一名字，表格只剩一行，但分页仍显示 `1–5 of 24`；无匹配结果时依然沿用总数24。源码 `user-view.tsx` 将 TablePagination.count 固定为 `_users.length`。

处理：迁移基线保留这个事实；修正分页语义时单独提交，明确 count 改用过滤结果以及空结果/最后页页码策略，并补充与排序、rowsPerPage 组合测试。不能先改掉原副本再据此宣称与上游一致。

## UP-02 / AM05：筛选后的全选作用于全部24人

分类：上游选择范围语义，已实测。只显示一个筛选结果时点击表头全选，工具栏显示 `24 selected`。源码传入所有 `_users` 的ID，而不是当前筛选结果。该语义是否调整，需要明确选择范围；不能仅看checkbox被勾选就报告正确。

处理：分别记录全数据、筛选集、当前页三个范围；忠实迁移先对照现有行为，增强版另选定目标契约，测试跨页保留、清空筛选和取消选择。

## UP-03 / AM03：全部已读后焦点丢失，Escape不关闭通知弹层

分类：原版交互问题，已实测。打开通知并点击“Mark all as read”，未读数变0，条件渲染移除了当前按钮，document.activeElement变为BODY。此时直接Escape，弹层仍在；重新聚焦弹层内View all再按Escape才会关闭。

处理：测试记录原始焦点与两种Escape行为，不删除键盘检查，也不将测试中的重新聚焦当作产品修复。迁移版后续修复时需要明确将焦点移到稳定元素并检查归还触发器，防止隐藏焦点问题破坏后续导航。

## DEMO-01 / AM06：Products只有过滤、排序、分页的外观与局部state

分类：免费模板的展示性实现，不归因于cormi。选Price: Low-High、过滤Women/Above $75或第2页之后，原24张商品卡和顺序不变。源码不将filter/sort/page用于产品数组。

处理：忠实迁移报告为控件状态与卡片展示，不能报告真实商品筛选/排序/分页通过。数据操作作为明确的新功能设计，需加载、失败、空结果、取消等状态；不在迁移中悄悄扩写完整电商业务。

## DEMO-02 / AM07：Blog补全与排序选项不处理文章列表

分类：展示性实现。搜索Whiteboard能出现候选，选中只是设置输入值；Oldest只改变选项文案，23张卡片保持原序列。New post未连接创建操作。

处理：分别验证补全交互和列表行为，不能把输入框出现候选称为文章搜索。编辑、详情、服务端搜索或分页另开增强议题。

## DEMO-03 / AM05、AM08：可点击按钮不等于CRUD和鉴权

Users的New user没有业务处理，行Edit/Delete只关闭菜单；Sign in对虚构凭据仍直接导航回首页，没有认证请求。账号Logout也没有相应处理器。

处理：这些原版UI保留，但迁移验收明确注明无真实能力。未来权限、身份、写入和服务端API验证不能靠这个免费模板原有代码来证明。

## CF-01 / AM02、AM09：cormi缺少等价的自定义路由错误边界

分类：已由当前框架与上游源码对照识别的迁移阻塞，尚未实现。原版根路由配置errorElement并使用useRouteError；cormi当前路由IR没有相应模块引用，通用RouteFailure不是原界面的等价替代。

关闭要求：设计错误组件引用及生成时机，确保页面lazy导入失败时错误组件已经可用；覆盖渲染错误、模块导入失败、嵌套边界向父冒泡、错误组件本身抛错、开发修复和生产行为；不靠删除原errorElement通过迁移。

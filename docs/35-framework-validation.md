# cormi 功能验收：Admin 是负载，不是产品主线

日期：2026-10-19。用户明确：移植 Admin 的目标是检验 cormi 的功能与可用性，不是替模板开发后台产品。P5d 的 Header 修复作为已有可选产物保留，后续不扩展；不要求修完 Users 分页、商品筛选、图表全部交互或模板无障碍问题才能完成框架。历史报告不改写。

## 配置代际修正

在 `packages/cormi/src/supervisor.ts` 中，静态编译通过不是永远有效的准入凭证。旧 worker 清理和新 worker 初始化都是异步边界。

当旧 worker 尚在清理时，输入从 B 改到 C，清理完成后重新核对编译输入指纹，丢弃 B 而不执行其初始化。如果初始化过程中输入发生变化，监听模式的 server ready 不直接转发；先关闭该过期实例，再处理最新输入。附加事件 `superseded` 区分 `before-start` 和 `before-ready`。这不是第二套 Cordis 生命周期，宿主、服务注入与销毁仍由原路径负责。

一次性命令可能已经写入文件或执行外部副作用，不因为事后输入改变而自动重放；`result` 不走 server-ready 的重试规则。对已知输入做校验也不是文件系统事务，不保证任意动态 I/O 被自动追踪。已经进入初始化的可信插件可能短暂获取资源；关闭不等于外部副作用回滚，不能宣称零停机切换或任何时刻绝不服务过期 HTTP 请求。

## 可复用测试与真实负载

[最小回归](../tests/launcher-supersession.test.ts)使用普通 CLI、真实子进程和 HTTP，不依赖 Admin/MUI，覆盖清理中更新、初始化中更新、清理中变成语法错误、显式 watch 文件更新、一次性命令不重放。

[Admin 驱动](../scripts/admin/framework.ts)仅用于新建且未运行的忠实迁移测试副本。它临时包装配置，将已有 Users 页面挂到 Cordis 插件，记录公开 runtime 标记，并通过受控文件变化测试 hooks 与 worker。私有测试模块和状态不传给浏览器，完成后恢复原配置、移除自己创建的探针、重新生成正常入口，并比对 src/public 哈希；不会触碰正在运行的旧试用目录或清除其锁。

真实负载必须安装当前 cormi tarball，明确声明测试使用的 `@cormijs/plugin-react`，不能借 workspace 的隐式提升。运行形式为 `node --import tsx scripts/admin/framework.ts --app <独立忠实副本> --out <不存在的证据目录>`。该命令会临时修改测试副本，不应对日常工作中的应用执行。

## 3. 已复现、需要保留的问题

**Users 的分页与过滤脱节。** 搜索后只剩1行，分页仍显示 `1–5 of 24`；在这个筛选结果下点击表头全选，工具栏却显示 `24 selected`。前者来自分页 count 使用原数组长度，后者来自全选传入原数组全部ID。选择范围应是全部数据、筛选集还是当前页，是必须明确的功能语义，不能只检查 checkbox 能勾选。

**通知弹层存在焦点问题。** 点击“全部已读”后，当前按钮被条件渲染移除，焦点落到 BODY，立即按 Escape 不关闭弹层。重新聚焦弹层中的 View all 再按 Escape 才能关闭。脚本如实记录这个原版行为；测试中的重新聚焦是继续测量的操作，不是产品修复。

**Products 与 Blog 中不少功能只完成了控件状态。** Products 的排序、过滤、分页不改变原24张卡片；Blog 的补全只填入输入框，排序选项不改变23张文章卡片。不能因为菜单可选就宣称真实过滤、排序或分页完成。

**CRUD 与鉴权不能凭界面推断。** Users 的 New user 没有处理器，行 Edit/Delete 只关闭菜单；Sign in 对虚构输入也会直接进入首页。这些需要和未来新增的真实业务操作分开验收。

上述事实逐条进入 UP-01/02/03 和 DEMO-01/02/03。未修改上游文件、未把占位按钮改成新功能再冒充原版，也未将所有失败归因于 cormi。详细来源与后续关闭条件见 [问题登记](admin/03-issue-register.md)。

## 4. 框架适配缺口已作为独立议题保留

**CF-01：自定义路由错误边界。** 原版根路由有 errorElement，其组件使用 useRouteError；cormi 当前路由IR和生成器尚无等价的自定义错误模块接口。通用 RouteFailure 与普通404不能自动替代原来的错误处理。本轮只完成源码对照与需求确认，没有实现或关闭这个缺口。

下一步 AM02/AM09 需同时验证唯一 root/router、App 位于 Router 内、pathless layout、lazy 与边界的加载顺序、页面渲染抛错、模块加载失败、子级错误向父边界传播和恢复。StrictMode、原 tsconfig 工具引用、React/Router 依赖差异、`src` alias 以及 `/admin/` 下的资源路径也各自记录。不能为了让构建通过，删除布局、错误组件、图表或关闭类型检查。
